# デザイン依頼：川崎タカシ「独自指数＆投票システム」体験デモ（スマホ・黒・高級）

## 依頼の要点

競馬予想家・川崎タカシが次に発売する**高額商材**のステップメールの中で、読者に**触ってもらう体験デモ**をデザインしてください。
川崎の競馬予想AI（独自指数＆投票システム）は非公開で、本物は誰にも見せません。このデモは、本物を見せずに「中でこれだけの処理が走っている」「この道具は格が違う」と感じてもらうための**見本の画面**です。数字はすべて架空のサンプルです。

- メールに「触ってみる」ボタンを置き、その先で開くWebページ（スマホ縦画面がほぼ全て）
- 1〜2分で終わる。読者の操作は軽く（レースを選ぶ・ボタンを押す・スライダーを動かす程度）
- **全画面を黒で統一し、高級感を最優先**する。安い予想ソフトや「ゲーム」に見えたら失敗

成果物は、HTMLのプロトタイプ（実際に動くもの）と、実装用のハンドオフ（デザイントークン・各画面の仕様・アニメーションの仕様）です。以前の `design_handoff_kawasaki_club_lp/` や `docs/member-lp/handoff/` と同じ形でお願いします。

## 試作から直したいこと

依頼者の感想は「なかなかいいが、**ちょっとふざけている感じがする**。高額で売る商材なので、**高級な感じのデモ画面**にしたい」でした。原因は次の点だと考えています。

1. 判定と資金の画面だけ**白**に切り替わる → **全画面を黒に統一**する
2. 見出しの書体（Dela Gothic One）が丸っこくポップ → **品のある書体**にする
3. 判定の「買い」「見送り」が、**斜めにバウンドして押されるハンコ風** → 静かに、重く確定する見せ方にする
4. ネオンの多色（シアン・マゼンタ・黄緑など）がにぎやか → **金とプラチナ（銀白）を中心に、色数を絞る**
5. 角の丸いカード、跳ねる動き、点滅 → 細い罫線、ゆっくりした確かな動き

## トーン＆マナー：高級な私設端末

イメージは次の3つの掛け合わせです。

- **プライベートバンクの専用端末**：選ばれた顧客だけが見られる、静かで精密な画面
- **高級機械式時計の文字盤**：黒い文字盤、金のインデックス、極細の目盛り、正確に動く針
- **F1チームのテレメトリー画面**：大量のデータが正確に流れ続ける緊張感

具体的には：

- **背景**：深い黒（純黒ではなく、ごくわずかに温かみか青みのある黒）。うっすらとした質感や、ごく弱い光のにじみはよい
- **金**：川崎のブランド色。シャンパンゴールド寄りの落ち着いた金を、罫線・数字・確定表示など限られた場所に使う。金のグラデーションは控えめに（安っぽい金ピカは避ける）
- **プラチナ**：本文やデータの数字は、真っ白ではなく少し落とした銀白
- **データの色分け**：必要な箇所（解析画面の6種類のデータなど）だけ、彩度を落とした色を最小限に
- **書体**（Google Fonts で読み込めるものに限る）
  - 見出し：品のあるセリフ体や明朝体（例：Shippori Mincho B1・Zen Old Mincho、欧文は Cormorant Garamond など）。または極細〜中太の洗練されたゴシック。太く丸いポップ体は使わない
  - 数字・ラベル：精密な等幅書体（例：JetBrains Mono・IBM Plex Mono）か、数字の美しいセリフ体。桁はそろえる
  - 英字の小さなラベル（INDEX ENGINE、BET CONTROL など）は字間を広げて上品に
- **余白**：詰め込まず、ゆったり取る。情報量は多くても、整然と並んでいること
- **動き**：ゆっくり、滑らか、確実に。数字のカウントアップ、線の上を流れる光、行の並べ替え、目盛りが満ちていく、など**データが動く演出**に集中する。バウンド・点滅・揺れは使わない
- **確定の演出**：判定が出る瞬間は、この体験の山場。高級時計の針が止まるように、金の細い枠が引かれて文字が静かに浮かぶ、などの格調ある見せ方を
- **避けるもの**：白い画面、ポップな丸文字、ハンコ・スタンプ風、バウンド、点滅、絵文字、ネオンのにぎやかな多色、「今すぐ！」系の煽り、安っぽい金ピカ、ゲームのようなUI

## 画面の流れ（6画面）

上部に常に「独自指数＆投票システム」と川崎の顔アイコン、「DEMO」表示、5段階の進み具合（レース／解析／指数／判定／資金）を出す。
画面下部に常に「表示される数字はすべてデモ用のサンプルです」を出す（小さく、品よく。ただし読める大きさで）。

### 1. レースを選ぶ
- 見出し：**完璧な指数 × ベットコントロール**（川崎のnote記事の見出し）
- 説明：レースを1つ選んでください。指数の計算から「買う・買わない」の判定まで、システムの流れをそのまま体験できます。
- コマンド入力欄の演出：`takashi@index ~ $ select --race`（カーソル）
- 架空のレースカード3つ（タップで次へ）
  - 京都11R デモ記念（G3） 芝2200m・晴・良 14頭 → 判定「買い」
  - 東京11R サンプルステークス（OP） ダ1600m・曇・稍重 16頭 → 判定「買い」
  - 中山10R テスト特別（3勝） 芝1200m・雨・重 16頭 → 判定「見送り」
- 注記：デモ用の架空のレースです。実在のレース・馬ではありません。

### 2. 解析（見せ場・約7秒、自動で進む）
- 上部に数字のタイル4つがカウントアップ：読み込んだレース（過去10年）34,812／1頭あたりの分析項目 412／予測投票数シミュレーション 1,200,000／計算時間 2.84s
- 中央：**川崎の顔**（円形）＝指数エンジン。周りを時計の目盛りのような輪がゆっくり回る
  - 左：6種類のデータ（「過去10年の結果」「血統」「調教タイム」「馬場・展開」「予測投票数モデル」「オッズ推移」）から、中央へ光の粒が流れ込む
  - 右：出走馬（馬番を枠の色で）へ光が流れ、計算が終わった馬から指数の数字が出る
- 下：処理ログが流れる（例 `[load] 過去10年 34,812レースを読み込み`、`[model] 予測投票数モデル 起動`、`[ev] 7番 期待値 1.24 ▲ 1.00超え`、`[ok] 解析完了`）
- 終わると「指数を見る」ボタンが押せるようになる

### 3. 指数と期待値
- 表の列：馬番（枠の色）／馬名＋指数の棒／予測勝率／予測オッズ／期待値
- 馬番順に出て、指数の棒が伸びたあと、**指数の高い順に並べ替わる**
- 上位4頭に印（◎○▲△）、**期待値が1.00を超えた馬は金で強調**
- 説明：期待値＝予測勝率×予測オッズ。1.00を超えた馬だけが買う候補になります。オッズは締切時点の予測値です。

### 4. 判定（山場）
- 「買い」または「見送り」を大きく表示（**ハンコ風にしない**。格調ある確定表示）
- 買い：期待値1.00を超えた馬の名前と値。下に「ベットコントロール」として、予算1万円の配分（例：単勝 7 4,000円／馬連 3-7 3,500円／ワイド 3-7 2,500円、配分の棒つき）
- 見送り：期待値1.00を超える馬がいません。このレースは買いません。投票額 0円。「買わないレースを決めるのも、指数の仕事です。」
- 締めの一言：**予想ではなく、答え合わせ。**（記事の「言わば【答え合わせ】をするような商品」から）
- ボタン：資金の増え方を試算する／別のレースで試す

### 5. 資金シミュレーター
- 軍資金：3万／5万／10万のボタン＋スライダー（1万〜30万）。期間：スライダー（1〜12か月）
- 結果：○か月後の資金（大きく）、利益、月ごとの推移グラフ、1か月後・3か月後・半年後・1年後の表
- 計算式（**変えないでください**。記事の表と一致します）：1か月で資金が1.36倍（＝1 + 投票額は軍資金の3倍 × 月8開催 × 1.5%）
  - 3万円 → 1か月後 40,800円／半年後 189,826円／1年後 1,201,125円
  - 5万円 → 1か月後 68,000円／半年後 316,376円／1年後 2,001,875円
- 条件の注記（必ず表示）：月8開催／1日の投票額は軍資金の3倍／月間回収率101.5%／資金が増えたら投票額も同じ割合で増やす（複利）。回収率101.5%が毎月続いた場合の計算です。実際の回収率は月ごとに変わり、投票額が大きくなるとオッズが下がることもあります。

## 守ってほしいこと

- 「デモ用のサンプル」の注記は、画面下の常時表示を含めて**消さない**（実績や予想と誤解させないため）
- 実在のレース名・馬名・騎手名は使わない
- 文言は上記のとおり。足す場合は、煽り表現を避けて短く
- 動きを減らす設定の端末では、アニメーションなしで最終状態を表示する
- 横スクロールが出ないこと（390×844、375×667、360×640 で確認）
- 外部の画像・動画は使わない（使う絵は川崎の顔だけ。必要な装飾は CSS・SVG・Canvas で）
