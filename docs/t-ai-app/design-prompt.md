# デザイン依頼：T-AI 会員サイト（プロトタイプ・競馬新聞デザイン）

## 依頼の要点

競馬予想家・川崎タカシの確率エンジン **「T-AI」** の**会員サイト**のプロトタイプをデザインしてください。
販売LP（あなたの v4「T-AI新報」、公開中 https://t-ai.clubkawasaki.net ）で申し込んだ会員さんが、毎週ログインして使う画面です。

- 目的：会員さんが**「本物の競馬予想AIを自分の手で触っている」**と感じること。UIだけでなく、UX（触ったときの気持ちよさ・反応・流れ）まで作り込んでください
- デザイン：**LPと同じ競馬新聞の世界観**（紙・墨・赤、赤ペン、判子、罫線）。LPが「号外」なら、会員サイトは**毎週届く「会員専用の競馬新聞」を、指で操作できるようにしたもの**
- 端末：**スマホがほぼ全て**。片手・親指で操作できること。PCでも崩れないこと
- 今回は**プロトタイプ**です。データは全て見本（サンプル）で構いません。あとで本物のデータに差し替えるので、データとデザインを分けて作ってください（下の「データ」の章）

成果物は前回と同じ形でお願いします。
1. HTMLのプロトタイプ（実際に動くもの、ビルドなし）。`t-ai-app/index.html` として、そのまま置ける形
2. 実装用のハンドオフ `README.md`（デザイントークン・各画面の仕様・動きの仕様・追加した文言の一覧）

## 世界観：「指で操作できる、会員専用の競馬新聞」

- 地は新聞紙の色、文字は墨、強調は赤。LPのトークンをそのまま使う（紙 `#f2ecdf`／墨 `#1b1814`／赤 `#c1121f`、見出し Zen Kaku Gothic New、数字 Oswald、手書き Zen Kurenaido）
- 競馬新聞の「馬柱」「印」「出馬表」の形を借りて、**見慣れた紙面がそのまま動く**感じにする
- T-AIの数字（勝つ確率）は、紙面に**赤ペンで書き込まれる**ように見せる。計算中は「輪転機が回っている」「活字が組まれていく」ような演出もあり
- 毎週見る画面なので、**派手さより、読みやすさと操作の速さ**を優先。演出は最初の1回だけ、2回目以降は短くする
- 避けるもの：ゲームのようなUI、点滅、絵文字、白一色の管理画面っぽさ、黒×金（それはデモの世界観）

## 画面の構成

画面下に固定のタブ（例：今週／レース／買い目／成績／マイページ）を置き、親指で切り替えられるようにしてください。タブの名前・数はデザイナーの判断で構いません。

### 1. ログイン
- 「T-AI新報 会員版」の題字と、メールアドレスの入力欄だけのシンプルな入口
- プロトタイプなので、**何を入れても（空でも）入れる**ようにしてください
- 本番はメールに届くリンクでログインする予定です（パスワードなし）。それに合う画面にしてください：「ログイン用のリンクを送りました」の画面も1枚

### 2. ホーム（今週の紙面）
- その週の「一面」。開催日・開催場、全レースの数、**T-AIが計算を終えたレース数**
- 今週の注目（例：重賞、T-AIの勝つ確率が高い馬がいるレース）
- 「最終更新 ○月○日 ○:○○」の表示（毎週、出馬表が確定したら更新される想定）

### 3. レース一覧
- 日付 → 競馬場 → レース（1R〜12R）を選ぶ。競馬新聞の目次のような一覧
- 各レースに：発走時刻・レース名・芝/ダート・距離・頭数・**T-AIの1番手の馬と勝つ確率**
- 「計算済み／出馬表待ち」の状態の違いが分かること

### 4. レース詳細（いちばん大事な画面）
- 出馬表の形：枠・馬番・馬名・騎手・斤量・前走など、競馬新聞の馬柱を簡略にしたもの
- 全馬に**T-AIの勝つ確率（%）と順位**。棒グラフ、または赤ペンの数字。合計100%
- 並び順を「馬番順／確率順」で切り替え
- 確率の高い馬に赤ペンの丸・印（◎○▲△）を自動で付ける
- 確率帯ごとに見え方を変える（例：30%以上は赤丸、5%未満は薄く）
- 初めて開いたときは、**数字が計算されていく演出**（1〜2秒）。2回目からは即表示
- 注記の欄：例「※海外から来た馬など、日本での出走歴がない馬は、確率が低く出ることがあります」（該当する馬がいるレースだけ表示）

### 5. 組み合わせの確率
- 馬連・ワイド・3連複をタブで切り替え
- **確率の高い順**に組み合わせを並べる（上位20件程度＋「もっと見る」）
- 馬番の組み合わせは、競馬新聞の買い目のような見た目で

### 6. 買い目をつくる（いちばん「触っている」と感じる画面）
- 馬番のボタンを親指でタップして、**軸と相手**を選ぶ
- 選んだ瞬間に、その買い目の**点数と、当たる確率（合計）**がその場で計算されて出る
- 券種（単勝・馬連・ワイド・3連複）、買い方（流し・ボックス）を切り替えられる
- 予算を入れると、点数あたりの金額を出す（均等配分で構いません）
- 計算は画面の中のJavaScriptで行う：単勝の確率から組み合わせの確率を出す計算式（Harville法）で構いません。本番で計算方法を差し替えられるように、計算の部分を1か所の関数にまとめてください
- 文言の例：「この買い目が当たる確率 23.4%」

### 7. 成績（答え合わせ）
- 終わったレースについて、T-AIの確率と、実際の着順を並べて見せる（1着の馬に赤丸）
- 確率帯ごとの集計表：「予測した確率の平均」と「実際に勝った割合」と頭数。LPの「第3面 成績」の表と同じ形
- 月ごとに切り替え

### 8. マイページ
- 会員名、プラン名、**利用期限**（例：2027年12月31日まで）
- お知らせ（運営からの連絡）
- 公式LINEへのリンク（https://lin.ee/uDgbNni ）、ログアウト

## データ（あとで本物に差し替えるため）

- 見本データは、HTMLの中に**1つのJavaScriptのデータ**としてまとめてください（例：`const DATA = {...}`）。画面はこのデータから組み立てる
- 本番では同じ形のデータを、データベースから読み込みます。下の形に合わせてもらえると、差し替えが楽です

```js
const DATA = {
  updatedAt: '2026-11-21T09:00:00+09:00',
  member: { name: '会員 太郎', plan: '2027年末まで 長期完全制覇プラン', until: '2027-12-31' },
  races: [
    {
      id: '202605050811',          // レースの番号（例）
      date: '2026-11-22', venue: '京都', no: 11, name: 'サンプル記念（G1）',
      start: '15:40', surface: '芝', distance: 1600, status: 'ready', // ready=計算済み / waiting=出馬表待ち / done=レース終了
      horses: [
        { no: 1, gate: 1, name: 'サンプルホース', jockey: '騎手名', weight: 57, last: '前走 3着',
          prob: 0.234, rank: 1, note: null, result: null }  // result はレース後の着順
      ]
    }
  ]
};
```

- 見本の内容：1日分・1〜2場・**全レース（12R×場数）**があると本物らしく見えます。馬名・レース名は**架空**にしてください（実在の馬名は使わない）
- 確率は1レースの合計が100%になるように
- 画面のどこかに小さく「※画面はプロトタイプです。数字はすべて見本です」

## 動き・操作感

- タップしたら必ず反応する（押した感じ・沈むボタンはLPと同じ）
- 画面の切り替えは速く（0.2〜0.3秒）。待たせる演出は最初の1回だけ
- 赤ペンの線・丸は、LPと同じ描かれ方（SVG の stroke-dashoffset）
- 「動きを減らす」設定の端末では、演出なしで表示
- 長押しで文字選択されないように（LPで不具合が出たため。`user-select: none` と `-webkit-touch-callout: none`）。ただし入力欄は除く
- 横にはみ出してスクロールしないこと（360px幅でも）
