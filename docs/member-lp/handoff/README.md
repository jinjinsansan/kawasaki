# Handoff: 川崎クラブ 長期会員募集LP（A 縦スワイプ／B 縦スクロール読書型）

依頼書：`docs/member-lp/design-prompt.md`（コミット 7d3091c）に沿って制作。

## Overview
主宰者・川崎タカシの手記（約4,500字）を最後まで読んでもらうためのページ。同じ原稿・同じ部品で、読ませ方だけが違う2案を用意した。
- **A案 `a.html`**（採用）：縦スワイプ。1画面1〜3段落、縦書きの章扉、決め台詞は単独の画面（全59画面。読了前は50画面）。前の版は `a_v1.html`
- **B案 `b.html`**：縦スクロールの読書型。段落が静かに現れる、読了バーと「残り約○分」、目次
- `compare.html`：2案をスマホ枠で並べて読み比べる確認用ページ（本番には不要）

## About the Files
**本番用のコード**として書いている（素のHTML/CSS/Vanilla JS、ビルドなし）。採用した案を `index.html` にリネームして、そのままVercelに置ける。
外部から読み込むのは Google Fonts と `platform.twitter.com/widgets.js` だけ。

```
member/
  a.html / a.js      A案
  b.html / b.js      B案
  content.js         原稿データ（全文）と共通部品の描画。A・B共通
  shared.css         デザイントークンと共通部品
  ogp.html           共有用画像（1200×630）の元データ → assets/ogp.png
  assets/ogp.png
  compare.html       読み比べ用（本番不要）
  captures/          390×844のキャプチャ
```

## 原稿の扱い
- 本文はすべて `content.js` の `CH` 配列にあり、一字一句そのまま。手を加えたのは段落と画面の区切りだけ。
- 見出しの「⚠️」は金の「◇」に置き換えた（`ch.warn`）。
- 原稿の外から足した文言は、依頼書で指定されたもの（「定員に達した時点で、予告なく募集を締め切ります」「分かり合えた方だけ、扉をお開けください」「このプランで参加する」）と、UIのラベル（「上へスワイプして読む」「読了まで約8分」「続きから読む」「プランを見る」「プラン一覧へ進む」「目次」、比較図の「そのまま買う／予想を売って」）だけ。
- 決め台詞7つは `K(前, マーカー部分, 後)` の形で、文は分けずにマーカーを引く範囲だけを指定している。

## 最後まで読んだ人にだけプランを見せる仕組み（A・B共通）
- 第7章と第8章は `locked:true` になっていて、**最初は描画すらしない**（HTMLにもない）。
- 扉のボタンを押すと次のように動く。
  1. `localStorage.kc_member_unlocked = '1'` を保存
  2. 扉が開く
  3. 第7章と第8章を追加で描画
  4. 1.9秒後に第7章へ移動
- 次に開いたときは、扉が開いた状態で表示され、ボタンは「プラン一覧へ進む」になる。表紙にも「プランを見る」が出る。
- 「続きから読む」：途中まで読んだ位置を保存しておき、表紙に案内を出す。
  - A案：画面の番号を `kc_member_a_pos` に保存
  - B案：スクロール位置を `kc_member_b_pos` に保存
- 申し込みのリンク先は `content.js` の `CTA_URL` で、全プラン共通（今は仮の `#`）。

- `?state=unlocked`：読了後の状態にする

## A案の仕様
- 誌面の装飾：
  - 各画面を細い罫線の枠で囲む（`.scr::before`）
  - 右下に章番号の透かし（`.scr[data-num]::after`、透明度7.5%）
  - 下の端にノンブル（`.folio`：KAWASAKI CLUB とページ番号）
  - 章扉と決め台詞の画面は地を `--paper-2` にする。決め台詞の画面には金の引用符を付ける
  - 章の最初の画面は、書き出しの一文字目を金で大きくする
  - 表紙に写真（`assets/takashi.jpg`）をアーチ枠＋セピア調で入れる。画面の高さが720px以下のときは写真を隠す
- はみ出しの判定は、`.scr-in` の高さを画面の内側の高さ（padding を除いた高さ）と比べて行う。章扉は判定しない
- 縦方向のスナップ（`scroll-snap-type:y mandatory`、`scroll-snap-stop:always`）で、1画面＝`100dvh`。
- PCでは幅520pxの中央カラムで表示し、左右は濃いめの紙色にする。
- 操作：
  - スワイプ、ホイール
  - ↓、PageDown、スペースで次へ
  - ↑、PageUpで前へ
  - Homeで先頭へ
- 上部に「第3章／全8章」と細い金の進捗バーを表示する。表紙では隠す。
- 画面が切り替わると、要素が0.22秒ずつ遅れて10px下からフェードインする（1秒）。
- 1画面に収めるための調整：画面からはみ出した場合は自動で `.dense` を付け、文字を15.5pxに縮める。さらにはみ出す場合は `.denser`（14.5px）にする。
  - 確認済み：390×844ではすべての画面が縮小なしで収まる
  - 確認済み：360×640では、縮小が必要なのはX埋め込みの画面だけ（投稿の高さを `100dvh − 400px` に切って対応）
- 画面リストは `a.js` の中で自動で組み立てている（章扉 → 本文の各画面）。

## B案の仕様
- 1カラム、最大幅は `21.5em + 48px`。
- PCでは左右の端を濃いめの紙色にして、紙の余白に見せる。
- 表紙は画面の高さいっぱいに表示する。スクロールで画面の高さの60%を過ぎたら、上部バーが降りてくる。
  - 上部バーの中身：現在の章、残り約○分、目次ボタン、2pxの読了バー
- 段落が画面に入ったら、12px下から0.9秒で現れる。
- 決め台詞のマーカーは、左から1.5秒かけて引かれる。
- 残り時間は「読める範囲の文字数 ×（1 − 読了率）÷ 500字/分」で計算する。
  - 読み終える前は、読める範囲を扉までとして計算する
  - 最後まで読むと「読了」と表示する
- 目次：下からシートが出る。扉を開けるまでは第7章と第8章を載せず、「— 第六章を読み終えると、続きの章が開きます —」と表示する。

## prefers-reduced-motion（動きを減らす設定）
フェード、マーカー、棒グラフ、扉の動きなど、アニメーションをすべて止めて、最初から表示した状態にする。
