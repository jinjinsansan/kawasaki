## 5. よくある直し方

**文言を直す**
1. `member/content.js` の `CH` の該当箇所を直す
2. 朗読にも入っている文なら、`docs/member-lp/voice/yomi.txt` の同じ段落も直して、音声を作り直す（下の「朗読」）
3. コミットしてプッシュ → 本番で確認

**画像を差し替える**
- **同じファイル名で上書きしない**（7日間キャッシュされるので、前に見た人には古い画像が出続ける）。名前を変える（例 `eriza2025-v2.webp` → `-v3`）か `?v=2` を付ける
- 的中画像・成績の画像は**数字に手を加えない**。切り抜きと縮小だけ
- 参考：エリザベス女王杯の画像は、川崎さんから「受付時刻15:13」版と「15:15」版の2枚が届き、川崎さんの指示で15:15版を使っている。15:15版は元のスクショを加工（拡大処理など）したように見える。加工していない撮ったままの画像が手に入れば、差し替えたほうが証拠として強い

**申込URLを変える**：`content.js` 5行目の `CTA_URL`（4つのボタン全部に効く）

## 6. 朗読（AI音声）

- 声は ElevenLabs のAI音声（川崎さん本人の声ではない。表紙と再生中の帯に「AI音声」と明記している。本人は録音の時間がないため、この方針で依頼者の了承済み）
- 読むのは手記の文章だけ。成績・挿絵・図・的中画像の画面は声なしで数秒見せる。プランは読まない
- 既定の速さは1.5倍（約8分）。帯のボタンで1〜2倍
- 作り方（リポジトリのルートで）：
  ```
  python -X utf8 docs/member-lp/voice/make_voice.py gen     # 変えた段落だけ声を作る（クレジットを使う）
  python -X utf8 docs/member-lp/voice/make_voice.py check   # 文字起こしして読み原稿と照合 → voice/_check.txt
  python -X utf8 docs/member-lp/voice/make_voice.py join    # 章ごとの mp3 と timeline.json を書き出す
  python -X utf8 docs/member-lp/voice/make_voice.py redo 2-5  # 2章の5段落目だけ作り直す（読み間違いの直し）
  ```
  必要なもの：Python（`pykakasi`・`requests`）、ffmpeg/ffprobe、環境変数 `ELEVENLABS_API_KEY_STAR`
- `yomi.txt` の書き方：`## 番号 名前` で章、空行で段落、先頭 `!` は章見出し、`@目印` は「この段落を読む間に出す画面」、`@目印 秒数` だけの段落は声のない間。読み間違えやすい語は かな に開いている（病棟→びょうとう、善人面→ぜんにんづら、元本→がんぽん、T-AI→「ティー エーアイ」 など）
- 作った声のかけら（`voice/_chunks/`）はローカルだけにあり、コミットしていない。これが残っているPCなら、直した段落だけ作り直せる。消えていると全部作り直しになる（約5,000字分のクレジット）
- **注意**
  - キーは表示しない・リポジトリに入れない
  - ElevenLabs のクレジットは他のプロジェクトと共用。このキーでは残高を確認できない。大きく作り直す前に依頼者に一言確認する
  - 画面の区切りを変えたら `@` の目印も合わせる（目印が見つからないと、その画面へ送られない）
  - join すると mp3 の URL に `?v=…` が付き直るので、古い音声がキャッシュに残らない
